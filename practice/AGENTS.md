# Practice Hub Instructions

Use this directory as a learner-owned architecture practice space. Keep every exercise in its own `practice/<slug>/` directory.

## Exercise setup

- Derive each exercise from a concrete code change, architecture decision, or trade-off.
- Create a `brief.md` that states the goal, context, constraints, acceptance checks, and progressive hints.
- Provide the smallest starter code and focused tests needed to make the exercise runnable when the surrounding toolchain is available.
- Do not create or reveal a complete reference implementation unless the learner explicitly asks for it.
- Keep exercises isolated from reusable skills, handbook knowledge, and production project sources.

## Review mode

- Treat learner-authored code as the answer. Do not overwrite it, complete it, or refactor it during a review unless the learner explicitly asks for an implementation.
- Run focused checks when practical, then assess the solution against the exercise constraints and the underlying architecture decision.
- Explain what is correct, identify the first important gap or trade-off, and offer one actionable hint before proposing a full solution.
- Distinguish failing behavior, missing tests, and design trade-offs. Invite a retry before revealing a reference implementation.
